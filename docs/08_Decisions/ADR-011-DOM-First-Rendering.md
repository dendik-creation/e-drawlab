# ADR-011 — DOM-first rendering, no game engine

## Status

Accepted — implemented 2026-09-01.

## Context

The first implementation drew every scene into a single Phaser canvas: splash,
home, all three journeys and the evaluation. It matched the storyboard closely,
but frame rate was unacceptable on the hardware the product targets, and worst
in the three simulators the product exists for.

Profiling the built app (see [[Render-Migration-Plan]]) found the cost was the
render model, not the scene content:

1. **The whole canvas is redrawn every frame**, whether anything changed or not.
   The backing store is `stage.width × DPR` — on a 2.2:1 landscape phone that is
   ~2400×1080 design px at DPR 2, about **10 MP per frame**. At that size the
   splash's own progress tween stalls before the app is usable.
2. **Every `Phaser.Text` is a canvas texture**, re-rasterised and re-uploaded on
   each `setText` — and the simulator panels are made of live readouts.
3. **`Graphics.clear()` + rebuild per repaint** for the trace preview, the 3D
   viewport and the drag ghosts, each already throttled by hand because it could
   not keep up.
4. **A WebGL filter mask** composited the Jalur PCB materi through an offscreen
   render target every frame, with hand-written culling on top.

The decisive measurement: **idle Home was as slow as the simulators** (4.6 fps
against 6.2). Nothing about the scene content explained that.

Phaser also decoded every registered audio track into an AudioBuffer;
`work_theme.webm` alone is 4.8 MB of Opus, which lands as well over 100 MB of
PCM on a phone's heap.

## Decision

**Render every scene as React DOM, with SVG for vector work. Remove Phaser.**

- The design frame is one composited CSS transform. Phaser's stage maths reduces
  exactly to `scale = min(vw/1920, vh/1080)`, so every Figma-authored coordinate
  keeps its meaning and the layout is unchanged (ADR-009 still holds).
- Vector content — schematic symbols, the PCB trace preview, the 3D casing —
  becomes SVG, generated by the same maths as before. Element counts are in the
  dozens, well inside what the browser handles without a scene graph.
- Pure logic is untouched: `circuits.ts`, `traceModel.ts`, `casingModel.ts`, the
  evaluation configs and question banks are content and rules, not rendering
  (ADR-003).
- `AudioDirector` keeps its API — profiles, crossfade, ducking, mute-as-a-fade,
  autoplay unlock — on a Web Audio backend. Loops stream through `<audio>`
  instead of being decoded, and fades are scheduled on the audio thread rather
  than stepped every frame.

## Alternatives

1. **Optimise the canvas build in place.** Rejected: the per-frame full-canvas
   redraw is inherent to the renderer, and the hand-written throttles, repaint
   caches and culling already in the code were the evidence that this path was
   exhausted.
2. **Keep Phaser for the 3D viewport and the schematic sheet only.** Rejected:
   it keeps a ~1 MB dependency and a permanently-redrawing canvas for two
   panels that SVG renders for free.
3. **Swap Phaser for a lighter canvas library.** Rejected: same render model,
   same cost profile.

## Consequences

Measured on a phone-sized viewport (873×393), before → after:

| Scene | Before | After |
| --- | --- | --- |
| home (idle) | 4.6 fps | 59.2 fps |
| desain-skema, drag komponen | 6.2 fps | 59.9 fps |
| jalur-pcb materi (scroll) | 3.9 fps | 60.2 fps |
| jalur-pcb, drag slider | 6.1 fps | 59.6 fps |
| cad-casing, orbit 3D | 6.6 fps | 59.6 fps |

Long tasks during interaction: **463 → 0**. JS bundle: **1 718,87 kB →
308,08 kB** (463,71 → 93,58 kB gzip).

Follow-on effects:

- Text is real text: selectable, sized by the browser, and legible at any stage
  scale without supersampling. Accessibility work (REQ-UX, [[Accessibility]])
  now has a DOM to attach to — buttons are `<button>`, the quiz progress is a
  `progressbar`, sliders carry `aria-valuenow`.
- Scrolling regions, drag capture and fullscreen use platform behaviour rather
  than reimplementations; the canvas build's workaround for firing
  `requestFullscreen` before Phaser's queued pointer event is gone.
- Scenes are components, so only the one on screen is mounted; the canvas build
  had to stop the previous scene by hand.
- ADR-006 (Stage 3 rendering) is settled by this: the casing preview is an
  orthographic SVG projection, no 3D library.
- Costs: DOM text metrics differ slightly from Phaser's, so the migration was
  checked screen by screen against captures of the canvas build; two real
  differences were found and corrected. Very large element counts would need
  care, but nothing in this product approaches that.
